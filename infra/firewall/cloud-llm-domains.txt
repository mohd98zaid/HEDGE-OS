# PROJECT HEDGE — Cloud LLM Egress Denylist (R10.8)
#
# This file is the single source of truth for the set of fully-qualified
# domain names that the Ollama_Infrastructure host MUST NOT be able to
# reach over the network. The egress firewall (`egress-deny.rules`) is
# generated from this list.
#
# Format
# ------
# One domain per non-empty, non-comment line. Lines beginning with `#` are
# ignored. Trailing whitespace is stripped. The matcher is suffix-based:
# adding `openai.com` blocks `api.openai.com`, `cdn.openai.com`, etc.
#
# Coverage philosophy
# -------------------
# We block at three layers:
#   1. Provider apex domains and their well-known subdomains (this file).
#   2. Provider IP CIDRs at the L3 layer (see `egress-deny.rules` § "CIDRs").
#   3. SNI (TLS Server Name Indication) at the L4 layer (see § "SNI sets").
#
# When in doubt, prefer adding a new entry over removing one. The Ollama
# host has zero legitimate need to talk to public LLM providers; if a
# Warm_AI_Pipeline component requires reasoning, it must reach a *local*
# Ollama container on the private Docker network.
#
# References
# ----------
# - Requirements §10.8: "Ollama_Infrastructure SHALL NOT make outbound
#   calls to any cloud LLM provider."
# - Design § Components § Ollama_Infrastructure: "Egress to public LLM
#   providers is firewalled at the host level."
